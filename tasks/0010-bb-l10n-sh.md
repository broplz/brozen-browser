## Goal
`scripts/bb/l10n.sh` replaces the GitHub-heavy part of Zen's `scripts/download-language-packs.sh` (a full
`git clone` of `mozilla-l10n/firefox-l10n` on every run): it keeps a bare mirror in a cache dir, fetches only the
pinned commit with `--depth 1`, and materializes `locales/firefox-l10n/` with a sparse checkout of just the
languages we ship. ADR-0002 Решение 4, the "Кэш" table, row `firefox-l10n`. Wiring it into a release build is
out of scope (no package.json / Zen script edits).

## Definition of Done
1. `bash -n scripts/bb/l10n.sh` → exit 0, no output.
2. `/bin/bash scripts/bb/tests/l10n_test.sh` → last line `PASS`, exit 0. The test builds under `mktemp -d` (`$T`), with
   `GIT_CONFIG_GLOBAL=/dev/null`:
   - an "upstream" repo `$T/up` (`uploadpack.allowAnySHA1InWant true`) with dirs `en-US/ a.ftl`, `ru/ a.ftl`,
     `nb-NO/ a.ftl`, `de/ a.ftl`, two commits; the pinned hash = the FIRST commit;
   - a fake repo dir `$T/repo` with `build/firefox-cache/l10n-last-commit-hash` (the hash, no trailing newline),
     `locales/supported-languages` = `ru\r\nnb\r\n` (CRLF on purpose), `locales/language-maps` = `nb:nb-NO`;
   - env `BB_REPO_DIR=$T/repo BB_L10N_CACHE=$T/cache BB_L10N_URL=$T/up BB_LOG_DIR=$T/logs`.
   It asserts, with a message on failure:
   a. first run → exit 0; `$T/cache` is a bare repo (`git -C $T/cache rev-parse --is-bare-repository` → `true`);
      `$T/repo/locales/firefox-l10n/` has exactly the top-level dirs `en-US`, `nb-NO`, `ru` (plus `.git`), not `de`;
      `git -C $T/repo/locales/firefox-l10n rev-parse HEAD` = the pinned hash; stdout has `l10n: fetched <hash>`;
   b. second run with `BB_L10N_URL=$T/nowhere` (unreachable) → exit 0, stdout has `l10n: cached <hash>`, same checkout;
   c. the hash file names a commit that is in neither the cache nor upstream → exit 1, stderr names the hash;
   d. the log dir has a log whose footer is `<== step: l10n exit=0` for run (a).
3. The test writes only under its `mktemp -d` and removes it.
4. `grep -c -E "git clone|rm -rf ~|config --global" scripts/bb/l10n.sh` → `0`.
5. `scripts/agents/diff.sh tasks/0010-bb-l10n-sh.md --names` lists only allowed_paths.

## Notes from teamlead
- Inputs (all relative to `BB_REPO_DIR`, default `$BB_ROOT` from `scripts/bb/lib.sh` — source lib.sh, reuse `bb_log_open`
  and `step`; log basename `l10n`, one step named `l10n`):
  hash = contents of `build/firefox-cache/l10n-last-commit-hash` (no newline in the real file);
  languages = `en-US` + every non-empty line of `locales/supported-languages` with `\r` stripped (the real file has
  39 entries; do not edit it); each language maps through `locales/language-maps` (`<id>:<dir>`, e.g. `nb:nb-NO`),
  unmapped → the id itself — same rule as Zen's `get_code_for_language`.
- Cache: `BB_L10N_CACHE` default `$HOME/zen-bro/cache/firefox-l10n`, a bare repo (`git init --bare` when missing).
  Remote URL `BB_L10N_URL` default `https://github.com/mozilla-l10n/firefox-l10n`. If
  `git -C cache cat-file -e <hash>^{commit}` succeeds → no network, print `l10n: cached <hash>`; else
  `git -C cache fetch --depth 1 --progress "$BB_L10N_URL" <hash>` → `l10n: fetched <hash>`. Then
  `git -C cache update-ref refs/bb/l10n <hash>` (so a local fetch needs no allowAnySHA1InWant on the cache).
- Checkout into `locales/firefox-l10n` (the path Zen's script copies from): remove it, `git init -q`, 
  `git sparse-checkout set <dirs…>` (cone mode), `git fetch -q --depth 1 <cache> refs/bb/l10n`, `git checkout -q FETCH_HEAD`.
- Forbidden: `git clone` of upstream, `git config --global` (Zen's script does it), deleting anything outside the
  cache dir and `locales/firefox-l10n`. bash 3.2 (macOS /bin/bash), `set -euo pipefail`.
- ADR says v1 languages are en-US and ru, but the repo's `supported-languages` lists 39; the script reads the file, so
  the owner's answer (logged in docs/reports/decisions-needed.md) needs no code change. Do not hardcode `ru`.
- Agent Bash: run only `bash -n` and `/bin/bash scripts/bb/tests/l10n_test.sh`; never hit GitHub.
