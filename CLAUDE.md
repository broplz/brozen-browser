# BROzen BROwser (BB) — agent handbook

BB is a macOS-only fork of Zen Browser (itself a Firefox fork) for former Arc users. One owner
sets direction and makes the key decisions; AI agents do the work one task at a time. Sources of
truth: docs/adr/ (accepted decisions), tasks/<id>-*.md (your task), tasks/backlog.md (the queue).
If this file and an ADR disagree, the ADR wins — say so in ## Result.

## Repo map
- src/zen/        Zen's own code: flat files symlinked into engine/ at import (class 2 — plain edits)
- src/**/*.patch  Zen's 263 patches to Firefox (class 3 — hands off without allow_zen_patch)
- src/bb/         the BB layer: modules, patches/<epic>/<name>/{*.patch,README.md}, layer.yaml
- prefs/bb/ · configs/bb/ · configs/branding/bb/ · scripts/bb/   BB prefs, build flags, branding, product scripts
- scripts/agents/ the pipeline: build.sh, test.sh, diff.sh, layer_lint.py, triage_log.py, run_*.py
- engine/         Firefox source + objdir, generated by surfer. Never a deliverable, never read wholesale.
- tasks/ (TEMPLATE.md, backlog.md, approvals.txt) · docs/adr · docs/notes · docs/rebase · docs/reports · logs/ (git-ignored)

## Hard rules (hooks enforce them; a blocked call is not a bug — read the message, adapt)
1. One task per session; its file is named in the prompt (also $BB_TASK). Read it whole first.
   Edit only its allowed_paths plus the task file. Found something else? One line in
   tasks/backlog.md under "Found by agents", then move on.
2. The driver owns git branches: never switch, checkout, merge, rebase, push, fetch or reset.
   Commit small and often on the current branch: `<prefix>: <what>` (prefix from the task).
3. engine/ is generated. Build, lint and test only via scripts/agents/build.sh and test.sh —
   never mach, surfer, npm run build/import/export/reset-ff directly.
4. Never read raw logs or big trees: logs via `python3 scripts/agents/triage_log.py <log>`
   (build.sh/test.sh already print it); engine/ via Grep (glob/type + head_limit) then Read
   with offset/limit.
5. Strikes: 3 failed ui builds/tests or 2 failed full builds on one task → stop, fill
   ## Handoff, set status: blocked, commit, end. Same when a hook blocks what the task needs.
6. English everywhere (code, comments, commits, task files). No TODO without a task id.
7. Never touch: .claude/, CLAUDE.md, .github/, tasks/approvals.txt, package-lock.json,
   build/signing/, *.env, *secret*. Never install packages; ask via the backlog.

## Bash discipline (permission mode dontAsk: a denied call just fails — take another route)
- One plain command per Bash call, from the repo root. No `;` `&&` `||` `$(...)` backticks,
  variables, `cd`, heredocs, redirects into files, `tee`, `sed -i`, `cp`/`mv`. Files are made and
  changed only with the Write/Edit tools. Pipes only into head/tail/grep/wc/sort/uniq/cut.

## Commands
- scripts/agents/build.sh [ui|full]    import + build; ui ≈ 3 min, full ≈ 40 min (lock, log, triage)
- scripts/agents/test.sh lint [<dir>…]  mach lint zen + layer_lint; Zen mochitests per dir
- scripts/agents/diff.sh <task>         the task's diff vs its base, capped (what reviewers read)
- python3 scripts/agents/layer_lint.py <task>   ADR-0002 rules on the diff (qa and the merge run it)
- scripts/bb/patches.sh check|export|status      BB patches (once task 0005 lands)
